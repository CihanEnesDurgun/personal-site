## 🐛 Düzeltilen: `/api/security/data` → 500

### Belirti

Admin panelinde **Güvenlik** sekmesi açıldığında konsolda şu hata görülüyordu:

```
GET https://cihanenesdurgun.com/api/security/data 500 (Internal Server Error)
SYS-3001 — Güvenlik verileri alınamadı
```

### Kök neden

İki ayrı bileşen aynı `data/sessions.json` dosyasını paylaşıyor ama **farklı şema**
varsayıyor:

- **`lib/sessionManager.js`** dosyayı ilk oluştururken yalnızca `activeSessions`,
  `inactiveSessions`, `loginHistory` anahtarlarını yazıyor. `failedLogins` anahtarı
  **ancak ilk başarısız giriş denemesinde** ekleniyor (`logLoginAttempt`).
- **`server.js` → `/api/security/data`** ise dosyayı okuyup `sessions.failedLogins`
  üzerinde koşulsuz `.forEach(...)` çağırıyordu.

İlk deploy edilen sunucuda henüz hiç başarısız giriş olmadığından `failedLogins` anahtarı
mevcut değildi → `undefined.forEach` → `TypeError` → 500.

Aynı hatalı varsayım `logSuccessfulLogin` (`sessions.loginHistory.unshift`) ve
`logFailedLogin` (`sessions.failedLogins.unshift`) içinde de vardı; bunlar `try/catch`
ile sarılı olduğundan girişi bozmuyor ama ilgili kaydı sessizce düşürüyordu.

### Çözüm

Tek ve merkezi bir noktada — `readSessionsFile` — okunan nesnede üç dizi garanti altına
alındı. Mevcut diğer anahtarlar (`inactiveSessions`, `lastUpdated`) korunuyor:

```js
const parsed = JSON.parse(data);
parsed.activeSessions = parsed.activeSessions || [];
parsed.loginHistory   = parsed.loginHistory   || [];
parsed.failedLogins   = parsed.failedLogins   || [];
return parsed;
```

Bu, aynı dosyayı okuyan tüm tüketicileri (`/api/security/data`, `logSuccessfulLogin`,
`logFailedLogin`, oturum sonlandırma uçları) tek seferde güvene alır. İlk başarılı giriş
sırasında `logSuccessfulLogin` dosyayı geri yazdığından `failedLogins: []` kalıcı olarak
oluşur ve dosya kendini onarır.

## ℹ️ Kod Hatası Olmayan İki Konsol Mesajı

Aynı konsol dökümünde görülen şu iki durum **hata değildir**, düzeltme gerektirmez:

### `/api/admin/logs` → 403 (aralıklı)

`validateSession` hiçbir durumda istisna fırlatmaz; geçersiz oturumda `null` döner ve
`authenticateToken` bunu 403'e çevirir. Bu 403, **süresi dolmuş veya 15 dakika boşta
kalmış** bir oturumun (özellikle sayfa bfcache'ten geri yüklendiğinde eski token'la)
istek atmasından kaynaklanır. İlk yüklemede aynı uç başarıyla çalışıyordu ("50 log
dosyası yüklendi"). Beklenen davranış: ön yüz 403 alınca giriş sayfasına yönlendirir.

### CSP `.map` engelleri

```
Connecting to 'https://cdn.jsdelivr.net/.../chart.umd.min.js.map' violates ...
"connect-src 'self'"
```

Tarayıcı DevTools açıkken kaynak harita (`.map`) dosyalarını çekmeye çalışır; CSP bunları
engeller. Site işlevini etkilemez, yalnızca DevTools'ta hata ayıklama haritası yüklenmez.
İstenirse ileride CDN `.map` kaynakları CSP'ye eklenebilir, ancak güvenlik açısından
gereksizdir.
