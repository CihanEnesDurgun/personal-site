# 📄 Versiyon Notları - v0.1.11

_Yayın Tarihi: Mayıs 2026_

## 🌟 Genel Bakış

`v0.1.11` sürümü, blog yazılarına **akademik kaynakça (footnote) sistemi** kazandırıyor — markdown editörden tek tıkla üst indis kaynak eklenebiliyor, otomatik numaralandırılıyor ve yazı sonunda "Kaynakça" bölümünde toplanıyor. Yan tarafta admin panele "**Taslağa Çek**" özelliği geldi (yayındaki yazıları geri taslağa alma), yönetim oturumunda **JWT decoding hatası** giderildi ve server tarafındaki **session cleanup** akışı dayanıklılaştırıldı.

## ✨ Yeni Özellikler ve Geliştirmeler

### Akademik Kaynakça (Footnote) Sistemi
- **GFM Footnote Desteği:** Blog yazılarına `[^1]` referans ve `[^1]: ...` liste sözdizimiyle kaynakça eklenebiliyor. `marked-footnote` eklentisi `post.html` ve `markdown-editor/index.html`'e dahil edildi.
- **Markdown Editöründe Tek Tıkla Kaynak Ekleme:** Toolbar'a yeni bir `①` butonu eklendi; modal üzerinden kaynak metni girilince:
  - İmlecin bulunduğu konuma `<sup>` üst indis referansı yerleştiriliyor.
  - Yazının sonunda otomatik olarak "Kaynakça" bölümü oluşturuluyor / mevcut bölüme yeni li ekleniyor.
  - Kaynak metni içinde markdown (kalın, italik, link) desteği var; güvenli inline parse ile render ediliyor.
- **Otomatik Numaralandırma:** Yazının ortasına kaynak eklendiğinde / referans silindiğinde tüm üst indis ve liste numaraları belge sırasına göre yeniden hizalanıyor (`renumberFootnotes`). Referansı silinen kaynakların liste maddesi de otomatik kaldırılıyor.
- **Türkçeleştirme:** Eklentinin sr-only "Footnotes" başlığı, hem editör hem yayın tarafında görünür "Kaynakça" başlığına çevriliyor.
- **Yumuşak Kaydırma:** Referansa tıklanınca kaynakçaya, geri-referansa (`↩`) tıklanınca metne yumuşak geçiş; `scroll-margin-top: 35vh` ile hedef satır viewport'un üst-ortasına konumlanıyor.

### Admin Paneli — "Taslağa Çek"
- **Üç-Nokta Menüsünde Yeni Aksiyon:** Yayındaki / zamanlanmış yazıların kartlarında, üç-nokta dropdown'una "Taslağa Çek" eklendi (sadece `status !== 'draft'` durumunda görünür).
- **Tek Tıkla Yayından Kaldırma:** Mevcut `/api/posts/:slug/publish` endpoint'i `draft` durumunu kabul edecek şekilde genişletildi; yazının `publishDate` alanı taslağa çekilirken korunuyor (yeniden yayınlandığında referans kalsın diye).

### Markdown Editörü — Kapak Fotoğrafı Aksiyon Butonları
- **Buton Gizleme Davranışı Kaldırıldı:** Kapak fotoğrafı yüklendiğinde "Değiştir / Kaldır" butonlarını gizleyen kural çıkarıldı. Hover sırasında resim biraz daha karartılarak (`brightness 0.6`) buton okunabilirliği sağlandı; kullanıcı artık kapağı her zaman değiştirebiliyor.

## 🐛 Giderilen Hatalar

### Server — Session Cleanup Logger Sessiz Hata
- **Logger Imza Uyumsuzluğu:** `cleanupSessionData` ve `readSessionsFile` içindeki `Logger.error('...', error)` çağrıları, `Logger`'ın beklediği `{ error }` context formatında değildi. Error objesi `Object.keys()` ile boş döndüğü için hata mesaj/stack'i log dosyasına hiç yazılmıyordu (sadece `"Error during session cleanup:"` görünüyordu). Üç çağrı düzeltildi.
- **Defansif Default'lar:** `sessions.json` eksik anahtarla okunursa `sessions.activeSessions.filter(...)` ile `Cannot read properties of undefined` patlaması olabiliyordu. `activeSessions`, `loginHistory`, `failedLogins` alanları boş diziye fallback ediyor.

### Admin Auth — JWT Base64URL Decode Hatası
- **Base64 vs Base64URL:** JWT payload'ları **base64url** kodlu (`-` ve `_` içerebilir, padding `=` eksik olabilir), ama `atob()` standart base64 bekliyor. Belirli token'larda decode başarısız olup oturum bilgisi okunamıyordu. Hem `admin/auth.js` hem `admin/login.js` için ortak bir `decodeJWTPayload(token)` yardımcı fonksiyonu eklendi: `-/_` karakterlerini `+//` yapıp eksik padding'i tamamlıyor.
- **`auto-logout` Guard:** `sessionInfo.timeLeft` undefined/NaN olduğunda `setTimeout(..., NaN)` anında tetikleniyor ve kullanıcıyı login'e atıyordu. Sayı doğrulaması eklendi; geçersizse otomatik çıkış zamanlayıcısı kurulmuyor.
- **Login Sayfası Auth Kontrolü:** `checkAuth()` yalnızca `admin_session`'a bakıyordu; geçerli JWT (`admin_token`) varken kullanıcı tekrar login formuna düşüyordu. Artık her ikisi de kontrol ediliyor; geçersiz token temizleniyor.
